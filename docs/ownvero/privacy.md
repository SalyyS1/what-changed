# Privacy and permissions

**Evidence state: development-source guidance; no approved owner-workspace installer or completed native acceptance.**

The static website explains the product and contains a synthetic example. It has
no account, analytics, telemetry, project upload, customer URL field, or Tauri
desktop bridge. Local search reads the site’s public documentation index.

## Local workspace

The desktop core keeps planning, brief review, historical evidence, and portable
memory local. It does not require a remote language model. A project-root link is
optional for owner workspaces; local diagnostics keep their existing folder scope.

Owner-authored rules, requests, decisions, and exported Markdown can contain
sensitive business information. Review content before copying it to another tool.
Recognized secret filtering is not a guarantee that all sensitive prose is removed.

## Consented preview sessions

Development source includes a packaged browser runner with permission for each
selected test environment. It uses temporary profiles and opens previews in a
separate browser without the desktop IPC bridge.

Permission covers a named environment, roles, effects, and attempt. It is not a
blanket network or production-data grant. Browser isolation does not isolate the
target database. Packaging and enforceable network limits remain acceptance work;
the source preview makes no completed clean-Windows runner claim.

## Evidence and authentication

Authentication state, screenshots, and temporary profiles may be sensitive.
Text redaction does not reliably sanitize images or video. Avoid real customers,
payments, and production email when testing. Do not attach these artifacts to a
public issue or place them in a portable bundle.

Deleting a browser profile does not guarantee secure erase from backups, pagefiles,
or a compromised device. Treat evidence as your data and keep only what you need.

## Export and deletion

Review selected export sections before saving or sharing. Imported evidence stays
historical and cannot grant permission or accept a current candidate. App-owned
deletion and restore boundaries are documented in the architecture; exported files
you saved outside the app remain your responsibility.

The data identity remains dev.whatchanged.app during the transition. Uninstall
normally keeps history unless you explicitly choose deletion. See
[Migration](migration-guide.md) and the [legacy privacy policy](../../PRIVACY.md).
