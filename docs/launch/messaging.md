# Launch messaging

**Evidence state: available development fact sheet; Ownvero identity and exact release publication remain approval-gated.**

This owns the current draft positioning. Technical documentation and the release
manifest own implementation and artifact truth. G2 must approve the public name
and production assets. G3 must approve one exact version, hash set, notices, and
site claims before a binary upload or an enabled download.

## Hierarchy

- **Audience:** an owner making repeated changes to an AI-built app.
- **Headline:** “Build with AI. Stay in charge.”
- **Job:** preserve working behavior before accepting the next AI-made change.
- **Workflow:** record intent and confirmed rules; review a Markdown brief; inspect evidence; accept, reject, or defer deliberately.
- **Repeat value:** carry the last decision, preserved rules, and gaps into the next request.
- **Scope:** Windows desktop with a local workspace; static landing, documentation, and a synthetic browser example.
- **Call to action:** try the synthetic example or read the development guide. The download remains unavailable without an approved exact artifact.

## Evidence and limits

The owner workflow is development source, not the existing unsigned installer.
The website demo contains synthetic booking data and never runs a customer URL.
Runner implementation needs per-attempt consent and an isolated test environment.
Clean-Windows packaging, enforceable network limits, native performance, and real
owner rehearsals remain acceptance work.

A passed scenario describes its checked expectation and context. Owner acceptance
is a separate recorded decision. Blocked, stale, failed, unknown, manual, and imported
evidence keep their labels. An export does not grant execution permission.

The local core supports planning and historical review without an account, cloud
service, or remote model. An explicitly permitted preview session may use the
network. Do not repeat the legacy absolute no-network or single-process promise
as a description of the proposed runner-enabled product.

## Anti-claims

Never promise universal safety, complete security, every-app verification, zero
regressions, an autopilot that fixes or deploys an app, or automatic owner acceptance.
Do not turn a passing scenario into product certification or infer a proven root
cause from correlated machine evidence. Avoid invented customers, traction,
testimonials, pricing, and completed pilot or clean-machine evidence.

Factual AI-builder positioning is allowed: the owner uses an existing coding AI
and reviews a brief. Ownvero does not silently edit code, decide for the owner,
or grant permission merely because imported records mention a preview.
